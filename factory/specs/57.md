# Spec Issue #57: Kommandozeile meldet die Version (--version)

> Erzeugt vom Requirement-Loop (`xiaomi/mimo-v2.6-pro`, Runde 2); jedes AK hat der Testing-Pruefer auf Pruefbarkeit geprueft, bevor Tests entstehen.

## Ziel

Der Aufruf `python3 -m findings_report --version` gibt die Paketversion als einzelne Zeile `findings_report 0.1.0` aus und endet fehlerfrei; alle anderen Aufrufe verhalten sich wie bisher.

## Nicht-Ziele

- HTML-Ausgabe
- Pruefung der Berichte
- Aenderung anderer Kommandozeilenaufrufe
- Aenderung des Eingabeformats

## Akzeptanzkriterien

AK1: AK1: `python3 -m findings_report --version` gibt genau eine Zeile `findings_report 0.1.0` auf die Standardausgabe aus und endet mit Exit-Code 0.
Pruefung: Ein Test startet `python3 -m findings_report --version` per subprocess im Repo-Wurzelverzeichnis, vergleicht stdout mit genau `findings_report 0.1.0\n` und prueft returncode == 0.
AK2: AK2: `python3 -m findings_report --version` schreibt nichts auf die Fehlerausgabe.
Pruefung: Derselbe Test startet `python3 -m findings_report --version` per subprocess und stellt per Vergleich fest, dass stderr == "" ist.
AK3: AK3: Der Aufruf mit einer Berichtsdatei (`python3 -m findings_report bericht.json`) verhaelt sich unveraendert: mit einer gueltigen Berichtsdatei im Eingabeformat des Pakets endet er mit Exit-Code 0, gibt eine Berichtsausgabe ungleich der Versionszeile auf stdout aus und schreibt nichts auf stderr.
Pruefung: Ein Test schreibt eine Berichtsdatei im Eingabeformat des Pakets (wie in den bestehenden Tests), startet `python3 -m findings_report bericht.json` per subprocess und prueft returncode == 0, stderr == "" und stdout != "findings_report 0.1.0\n".
