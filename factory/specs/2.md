# Spec Issue #2: Bericht einlesen und prüfen (Kommandozeile)

> Erzeugt vom Requirement-Loop (`anthropic/claude-opus-5.5`, Runde 1); jedes AK hat der Testing-Pruefer auf Pruefbarkeit geprueft, bevor Tests entstehen.

## Ziel

Mit python -m findings_report <bericht.json> wird ein Prüfbericht aus einer JSON-Datei eingelesen und auf Gültigkeit geprüft (title nicht leer, verdict aus pass/warn/fail, findings als Liste mit id, title und severity aus CRITICAL/HIGH/MEDIUM/LOW/INFO). Das Ergebnis wird über Exit-Code und Ausgabe gemeldet.

## Nicht-Ziele

- Erzeugen einer HTML-Seite oder eines anderen Ausgabeformats
- Netzwerkzugriffe oder Einlesen mehrerer Dateien in einem Aufruf
- Prüfungen über die im Issue genannten Felder und Werte hinaus

## Akzeptanzkriterien

AK1: Gültiger Bericht → Exit-Code 0 und genau eine Ausgabezeile `OK: <Anzahl> Befunde`.
Pruefung: Ein Test schreibt einen gültigen Bericht mit z.B. 3 Befunden in eine temporäre Datei, ruft per subprocess `python -m findings_report <datei>` im Repo-Wurzelverzeichnis auf und prüft returncode == 0 sowie, dass stdout genau aus der einen Zeile `OK: 3 Befunde` besteht.
AK2: Datei existiert nicht → Exit-Code 2 und eine Meldung, die den Dateinamen nennt.
Pruefung: Ein Test ruft das Modul mit einem nicht existierenden Pfad wie `gibt_es_nicht_123.json` auf und prüft returncode == 2 sowie, dass dieser Dateiname in stdout oder stderr vorkommt.
AK3: Datei ist kein gültiges JSON → Exit-Code 2 und eine Meldung „kein gültiges JSON“.
Pruefung: Ein Test schreibt den Text `{kaputt` in eine temporäre Datei, ruft das Modul damit auf und prüft returncode == 2 sowie, dass `kein gültiges JSON` in stdout oder stderr vorkommt.
AK4: Ein Pflichtfeld fehlt (`title`, `verdict`, `findings`) → Exit-Code 2 und die Meldung nennt den Namen des fehlenden Feldes.
Pruefung: Ein Test erzeugt für jedes der Felder title, verdict und findings je einen sonst gültigen Bericht ohne dieses Feld, ruft das Modul auf und prüft jeweils returncode == 2 sowie, dass der Feldname in stdout oder stderr vorkommt.
AK5: `verdict` oder `severity` hat einen unerlaubten Wert → Exit-Code 2 und die Meldung nennt den Wert und die erlaubten Werte.
Pruefung: Ein Test ruft das Modul mit einem Bericht mit verdict `maybe` und mit einem Bericht mit einem Befund mit severity `URGENT` auf und prüft jeweils returncode == 2 sowie, dass der unerlaubte Wert und alle erlaubten Werte (pass, warn, fail bzw. CRITICAL, HIGH, MEDIUM, LOW, INFO) in stdout oder stderr vorkommen.
