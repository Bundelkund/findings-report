# Spec Issue #2: Bericht einlesen und prüfen (Kommandozeile)

> Erzeugt vom Requirement-Loop (`anthropic/claude-opus-5.5`, Runde 1); jedes AK hat der Testing-Pruefer auf Pruefbarkeit geprueft, bevor Tests entstehen.

## Ziel

Mit python -m findings_report <bericht.json> wird ein Pruefbericht aus einer JSON-Datei eingelesen und auf Gueltigkeit geprueft; gueltige Berichte liefern Exit-Code 0 mit einer OK-Zeile, ungueltige Exit-Code 2 mit einer erklaerenden Meldung.

## Nicht-Ziele

- Erzeugen einer HTML-Seite aus dem Bericht
- Pruefung weiterer Felder ausser title, verdict, findings und den Eintragsfeldern id, title, severity
- Netzwerkzugriffe oder Einlesen mehrerer Dateien in einem Aufruf

## Akzeptanzkriterien

AK1: Gültiger Bericht → Exit-Code 0 und genau eine Ausgabezeile `OK: <Anzahl> Befunde`.
Pruefung: Ein Test schreibt einen gueltigen Bericht mit zwei Findings in eine temporaere Datei, ruft python -m findings_report <datei> per subprocess im Repo-Wurzelverzeichnis auf und prueft returncode == 0 sowie dass stdout genau aus der einen Zeile 'OK: 2 Befunde' besteht.
AK2: Datei existiert nicht → Exit-Code 2 und eine Meldung, die den Dateinamen nennt.
Pruefung: Ein Test ruft das Modul mit einem nicht existierenden Pfad wie fehlt_xyz.json auf und prueft returncode == 2 und dass der Dateiname in stdout oder stderr vorkommt.
AK3: Datei ist kein gültiges JSON → Exit-Code 2 und eine Meldung „kein gültiges JSON“.
Pruefung: Ein Test schreibt den Text '{kaputt' in eine temporaere Datei, ruft das Modul damit auf und prueft returncode == 2 und dass 'kein gültiges JSON' in stdout oder stderr enthalten ist.
AK4: Ein Pflichtfeld fehlt (`title`, `verdict`, `findings`) → Exit-Code 2 und die Meldung nennt den Namen des fehlenden Feldes.
Pruefung: Ein Test erzeugt fuer jedes der drei Felder einen sonst gueltigen Bericht ohne dieses Feld, ruft das Modul auf und prueft jeweils returncode == 2 und dass der Feldname in stdout oder stderr vorkommt.
AK5: `verdict` oder `severity` hat einen unerlaubten Wert → Exit-Code 2 und die Meldung nennt den Wert und die erlaubten Werte.
Pruefung: Ein Test ruft das Modul einmal mit verdict 'maybe' und einmal mit einem Finding mit severity 'HUGE' auf und prueft jeweils returncode == 2 sowie dass der unerlaubte Wert und alle erlaubten Werte (pass, warn, fail bzw. CRITICAL, HIGH, MEDIUM, LOW, INFO) in stdout oder stderr vorkommen.
