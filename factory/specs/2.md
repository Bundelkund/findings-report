# Spec Issue #2: Bericht einlesen und prüfen (Kommandozeile)

> Erzeugt vom Requirement-Loop (`anthropic/claude-opus-5.5`, Runde 1); jedes AK hat der Testing-Pruefer auf Pruefbarkeit geprueft, bevor Tests entstehen.

## Ziel

Mit python -m findings_report <bericht.json> laesst sich ein Pruefbericht aus einer JSON-Datei einlesen und auf Gueltigkeit pruefen. Das Ergebnis wird ueber Exit-Code und Ausgabe gemeldet.

## Nicht-Ziele

- Erzeugen einer HTML-Seite oder einer anderen Berichtsdarstellung
- Netzwerkzugriffe oder das Laden entfernter Berichte
- Pruefung weiterer Felder ueber title, verdict, findings, id, title und severity hinaus

## Akzeptanzkriterien

AK1: Gültiger Bericht → Exit-Code 0 und genau eine Ausgabezeile `OK: <Anzahl> Befunde`.
Pruefung: Ein Test schreibt einen gueltigen Bericht mit 3 Findings in eine temporaere Datei und ruft per subprocess sys.executable -m findings_report <datei> auf. Er prueft returncode == 0 und dass stdout nach strip genau aus der einen Zeile 'OK: 3 Befunde' besteht.
AK2: Datei existiert nicht → Exit-Code 2 und eine Meldung, die den Dateinamen nennt.
Pruefung: Ein Test ruft das Modul per subprocess mit einem nicht existierenden Pfad wie 'gibt_es_nicht_123.json' auf. Er prueft returncode == 2 und dass dieser Dateiname in stdout+stderr vorkommt.
AK3: Datei ist kein gültiges JSON → Exit-Code 2 und eine Meldung „kein gültiges JSON“.
Pruefung: Ein Test schreibt den Text '{kaputt' in eine temporaere Datei und ruft das Modul per subprocess auf. Er prueft returncode == 2 und dass 'kein gültiges JSON' in stdout+stderr enthalten ist.
AK4: Ein Pflichtfeld fehlt (`title`, `verdict`, `findings`) → Exit-Code 2 und die Meldung nennt den Namen des fehlenden Feldes.
Pruefung: Ein Test entfernt fuer jedes der Felder title, verdict und findings einzeln dieses Feld aus einem sonst gueltigen Bericht und ruft das Modul per subprocess auf. Er prueft jeweils returncode == 2 und dass der Feldname in stdout+stderr vorkommt.
AK5: `verdict` oder `severity` hat einen unerlaubten Wert → Exit-Code 2 und die Meldung nennt den Wert und die erlaubten Werte.
Pruefung: Ein Test ruft das Modul per subprocess einmal mit verdict 'maybe' und einmal mit einem Finding mit severity 'URGENT' auf. Er prueft jeweils returncode == 2 und dass der falsche Wert in stdout+stderr vorkommt. Ausserdem prueft er, dass im ersten Fall pass, warn und fail und im zweiten Fall CRITICAL, HIGH, MEDIUM, LOW und INFO in stdout+stderr vorkommen.
