# Spec Issue #60: Jeder Befund in der HTML-Seite traegt seine ID als data-id

> Erzeugt vom Requirement-Loop (`xiaomi/mimo-v2.6-pro`, Runde 2); jedes AK hat der Testing-Pruefer auf Pruefbarkeit geprueft, bevor Tests entstehen.

## Ziel

Die HTML-Berichtsseite enthaelt pro Befund ein li-Element mit Attribut data-id, das die Befund-ID HTML-escaped traegt; am restlichen Seiteninhalt aendert sich nichts.

## Nicht-Ziele

- Reihenfolge der Befunde
- Badges der Befunde
- Zusammenfassungszeile
- alle anderen Texte der Seite

## Akzeptanzkriterien

AK1: Ein Bericht mit einem Befund der ID `F1` erzeugt ein `li`, dessen Start-Tag das Attribut `data-id="F1"` enthaelt.
Pruefung: Test erzeugt die HTML-Seite fuer einen Bericht mit genau einem Befund der ID 'F1', durchsucht die Ausgabe nach einem li-Start-Tag und vergleicht, dass dieses Tag den String 'data-id="F1"' enthaelt.
AK2: Ein Befund mit der ID `a"b<c` erscheint als `data-id="a&quot;b&lt;c"`, nie als rohes `a"b<c` im Attribut.
Pruefung: Test erzeugt die HTML-Seite fuer einen Befund der ID 'a"b<c', vergleicht dass ein li-Start-Tag den String 'data-id="a&quot;b&lt;c"' enthaelt und dass der rohe String 'a"b<c' in der gesamten Ausgabe nicht vorkommt.
AK3: Die HTML-Ausgabe eines Berichts ohne Befunde enthaelt den String 'data-id' nicht.
Pruefung: Test erzeugt die HTML-Seite fuer einen Bericht ohne Befunde und stellt fest, dass die Ausgabe keinen Teilstring 'data-id' enthaelt.
