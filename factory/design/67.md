# Design Issue #67 (v1)

> Architektur-Loop (`anthropic/claude-opus-5.5`, Runde 2); ein Pruefer anderer Modellfamilie nimmt es ab, bevor Dev beginnt. Dev folgt diesem Weg.

## Loesungsweg

In findings_report/render.py eine Hilfsfunktion _natural_id_key(fid) ergaenzen: s = str(fid).casefold(); enthaelt s keine Ziffer (re.search(r'\d', s) ist None), liefert sie (1, (s,)), sonst (0, tuple(int(t) if t.isdigit() else t for t in re.split(r'(\d+)', s))). re.split mit Gruppe liefert abwechselnd Text und Zahl, daher sind die Typen positionsgleich vergleichbar. An der Stelle, an der die Befunde bisher nach Schweregrad sortiert werden, wird der Schluessel zum Tupel (bisheriger Schweregrad-Rang, _natural_id_key(f['id'])); die Rangtabelle der Schweregrade und das gesamte HTML bleiben unveraendert. Zusaetzlich eine Testdatei tests/test_67_natural_order.py mit unittest anlegen, die je AK eine Eingabe-JSON in ein Temp-Verzeichnis schreibt, python -m findings_report eingabe.json ausgabe.html per subprocess ausfuehrt und die Reihenfolge der ID-Strings ueber ihre Fundstelle im HTML-Quelltext prueft.

## Dateien

- `findings_report/render.py`: Neue Funktion _natural_id_key (re aus der Standardbibliothek). Der Sortierschluessel der Befundliste wird zu (Schweregrad-Rang, _natural_id_key(id)); sonst keine Aenderung an Markup, Badges oder Zusammenfassung.
- `tests/test_67_natural_order.py`: Neue unittest-Datei mit vier Tests fuer AK1 bis AK4. Sie erzeugen die Seite per subprocess ueber python -m findings_report und vergleichen die Reihenfolge der ID-Fundstellen mit ['F1','F2','F10'], ['f1','F2'], ['F3','Alpha','zeta'] und ['F99','F1'].

## Blast-Radius

Nur die Reihenfolge der Befunde innerhalb eines Schweregrads in der HTML-Ausgabe. Bestehende Tests nutzen bereits natuerlich sortierte IDs (F1..F6, A1..A5) und bleiben unberuehrt; die Validierung ist nicht betroffen.
