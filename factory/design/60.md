# Design Issue #60 (v1)

> Architektur-Loop (`anthropic/claude-opus-5.5`, Runde 1); ein Pruefer anderer Modellfamilie nimmt es ab, bevor Dev beginnt. Dev folgt diesem Weg.

## Loesungsweg

In findings_report/render.py dort, wo pro Befund das Start-Tag des li-Elements erzeugt wird, das Attribut data-id ergaenzen: den Wert mit html.escape(str(befund['id']), quote=True) escapen und als data-id="..." in das li-Start-Tag einsetzen; vorhandene Attribute wie class bleiben unveraendert. Sicherstellen, dass auch jede sichtbare Ausgabe der ID (etwa vor dem Titel) per html.escape laeuft, damit der rohe String a"b<c nirgends in der Seite steht. Den String data-id nur im li-Tag erzeugen, nicht in CSS, Kommentaren oder im Seitenkopf, damit ein Bericht ohne Befunde ihn nicht enthaelt; Reihenfolge, Badges, Zusammenfassungszeile und alle anderen Texte bleiben gleich.

## Dateien

- `findings_report/render.py`: Das li-Start-Tag jedes Befunds erhaelt data-id="<html.escape(id, quote=True)>"; die sichtbare ID-Ausgabe wird, falls noch nicht geschehen, ebenfalls mit html.escape escaped. Sonst keine Aenderung.

## Blast-Radius

Nur das HTML-Markup der Befund-li; Aufrufer in __main__.py und die bestehenden Tests zu Badges, Zusammenfassung und Ort parsen spans bzw. Texte und bleiben unberuehrt. Keine Daten betroffen.
